本頁屬於「清單／進度類頁面」，採 Codédex 式深色扁平卡片：深色卡片＋細框線＋像素點陣標題字＋編號路徑＋鎖定內容用「???」樣式。精確顏色/間距/字重不在本文件定義，實作階段搭配前端 UI 相關 skills 產出。

## 3. UI 狀態清單

本頁的 view-model 需要明確涵蓋以下狀態（不得遺漏任一狀態的設計）：

- **locked（循序鎖定）**：因前一章未完成而鎖定，需與下方「內容準備中」視覺區分（不是同一種不可進入原因，見第 5 節待決事項）。
- **content-preparing（內容準備中）**：章節已解鎖但內容尚未到位（如目前第 1/2/4/5/6 章的狀態）。
- **loading**：資料載入中。
- **empty**：章節已解鎖、內容已到位，但複習卡/題目集合為空（理論邊界情況，仍需定義畫面）。
- **error**：資料載入失敗（網路/伺服器錯誤）。
- **in-progress（學習中）**：複習/測驗部分完成。
- **completed（已精熟）**：三項完成條件皆達成。

每個小節任務／複習卡在清單中也需要各自的卡片狀態（可完成／已完成／鎖定）,不是只有整頁層級的狀態。

## 4. 手機版策略

- **原則**：直向為主，不強制轉橫。
- **水平捲動限制在明確的容器內**（例如複習卡清單容器、題目選項容器），**禁止頁面層級（`document`/根容器）出現水平 overflow**。任何需要橫向捲動的內容，必須包在有明確邊界、有視覺提示（如捲動陰影/箭頭）的子容器裡，不能讓整個頁面變寬。

## 5. 學生端 metric visibility inventory

| 顯示項目 | 學生端可見 | 說明 |
|---|---|---|
| 逐題即時對/錯回饋 | 是 | 學習機制必要 |
| 精熟度過關門檻（如「精熟度 18.9% / 80%」） | 是 | 學習機制必要，用於判斷是否可進入下一階段 |
| 複習卡完成進度（如「複習進度 2 / 3」） | 是 | 學習機制必要 |

| 累積/總體正確率（跨多次測驗的彙總統計） | **否** | Owner 裁定收起，避免學生刷題衝高數字 |
| 連續答對 N 題的連擊（combo）顯示 | 是 | Owner 裁定：不算累積統計，是即時遊戲回饋，正常顯示 |
| 精熟度顯示（僅最高分＋版本號次要文字） | 是 | 見第 5.1 節第 1 項，格式已定案 |

## 5.1 待決事項

第一輪（2026-08-10）的 3 項待決事項已由 owner 全數裁定：

1. **精熟度雙版本顯示格式**：只顯示最高分，版本號以次要文字呈現（不做兩個分數並列）。
2. **locked 與 content-preparing 的視覺區分**：視覺上明確區分——兩者不可共用同一種鎖定圖示/文案，避免學生把「內容還沒寫好」誤解成「自己的進度不夠」。精確的圖示/文案設計留待實作階段（搭配前端 UI skills）。
3. **累積/總體正確率邊界——連擊顯示**：「連續答對 N 題」的連擊（combo）不算累積統計，是即時遊戲回饋，正常顯示，不受第 5 節「收起累積正確率」規則影響。

**目前沒有已知的阻塞性待決事項。**
