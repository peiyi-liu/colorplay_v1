## 1. 範圍

### 1.1 Sheet 結構與識別碼（identity）

Google Sheet 已重構為 5 個分頁，本文件只處理其中 3 個：

| 分頁 | 主要欄位 | 本文件範圍 |
|---|---|---|
| 各單元複習大廳 | 複習卡序號／章節／章節標題／小節／小節標題／子主題／子主題標題／卡片內容／附件 | 是 |
| 各單元隨機測驗題庫（小節測驗題庫） | 題庫序號／章節／小節／題目／選項A-D／正確答案／解析 | 是 |
| 章節總複習（章節總測題庫） | 題號／章節／題目／選項A-D／正確答案／解析 | 是 |
| 前測題目 | 題庫序號／題目／A-D／解答／難度／對應章節／對應內容 | **否，未來項目** |
| 後測題目 | 同上 | **否，未來項目** |

現有匯入腳本（`scripts/content/fetch-sheet.mjs`／`import-questions.mjs`／`import-review-cards.mjs`／`verify-sheet-db.mjs`）依照舊結構（單一「題庫」分頁＋`code`欄位）寫成，對新結構會直接匯入失敗（已實測：「題庫分頁缺少必要欄位：code」）。

### 1.2 兩種題庫的分流匯入

`各單元隨機測驗題庫`（小節測驗池）與 `章節總複習`（章節總測池）是兩個獨立來源，需分別匯入成兩個不同用途的題目池，不再合併成單一扁平題庫。

### 1.3 `產生題目識別碼` Google Apps Script

落地 `docs/roadmap-colorplay-next.md`「Approved content and publication decisions」已核准的機制：

- 綁定 Sheet 的 Apps Script command，對新題目/卡片列自動產生**全域唯一**序號，寫入受保護欄位，不重新計算既有值。
- 序號欄位＝永久識別碼欄位，兩個概念統一為一個機制。
- 網站與匯入器僅讀取並驗證序號，不寫回 Sheet。
- 交付物包含 owner 設定引導文件。

精確的 ID 格式、命名空間、既有資料回填方式，見第 4 節待決事項——本文件不預先假設答案。

### 1.4 複習卡多卡支援

改用 `複習卡序號` 作為卡片識別碼，取代原本以「小節:子主題:標題」雜湊出的識別碼，原生支援同一子主題下多張獨立卡片。顯示規則：卡片標題顯示子主題標題；同子主題下多張卡標題相同，僅靠複習卡序號排序區分先後。

### 1.5 結構 gate 與內容 review（兩層，性質不同）

- **結構層**（`verify-sheet-db.mjs --gate`）：機器可判定的格式錯誤（缺欄位、重複代碼、選項數不足等），錯誤即擋匯入，不需要人工判斷。
- **內容品質層**（`content-reviewer` agent，依 `docs/content/question-review-rubric.md` C1-C8）：**這是 LLM 初篩，不是最終判定**。LLM 找出可能有問題的題目（術語錯字、邏輯矛盾、與常識衝突），標記 UNSURE 的項目必須交由教師/owner 人工裁決；LLM 判定為有問題的項目也需要教師/owner 確認處置方式（採納修正建議／保留原文／其他），不能把 LLM 的初篩結果直接當成內容已審查完成的證據。

「內容完整」的判斷標準：結構 gate 通過 **且** 內容品質層的所有 FAIL/UNSURE 項目都有教師/owner 明確處置紀錄，才算完整——不只是看題目/卡片數量，也不是 LLM 跑完就算數。

## 4. 待決事項（Open Owner Decisions，按阻塞順序排列）

以下事項需要 owner 逐項裁定，未裁定前本文件不能轉為可核准 spec。按「阻塞其他項目的程度」由高到低排列：

1. **識別碼格式與命名空間**：`複習卡序號`／`題庫序號`／`題號` 是否為同一個命名空間下的全域唯一值（例如都用同一組遞增序列），還是三個分頁各自獨立的命名空間（例如複習卡跟題目可以有相同的數字但不算碰撞）？這決定 Apps Script 要不要跨分頁協調發號。
2. **既有資料回填（legacy backfill）**：目前資料庫裡已存在、由舊機制（雜湊識別碼）匯入的第三章內容，要不要重新產生新格式的序號？如果要，舊識別碼要保留當歷史對照還是直接取代？
3. **併發與碰撞處理**：如果兩個人同時在 Sheet 上新增列（例如 owner 跟未來的內容協作者），Apps Script 觸發時機是「編輯時即時觸發」還是「批次執行」？兩種都可能有序號碰撞風險，需要決定碰撞偵測與重試機制。
4. **Apps Script 執行身分**：這支 Script 綁定在 owner 的 Google 帳號下執行，還是要用服務帳號？這影響誰的權限被用來讀寫受保護欄位、以及 Script 停用/帳號變更時的維運風險。
5. **受保護欄位的權限範圍**：「受保護欄位」具體要限制哪些人可編輯（僅 owner／特定協作者／唯讀給所有檢視者）？Google Sheet 的保護範圍設定需要對應到這個決定。

## 5. 客觀不可行的選項

- 「序號欄位由前端或匯入器計算後寫回 Sheet」：與 `docs/roadmap-colorplay-next.md` 已核准規則衝突（網站與匯入器僅讀取並驗證，不寫回），排除。
- 「跳過內容品質層，只靠結構 gate」：無法偵測術語錯誤/邏輯矛盾，與 AGENTS.md 題庫品質要求衝突，排除。
